# 代码导航路由（index）

> 任何代码相关任务（实现 / 排查 / 理解 / 数据流 / 纯问答）的**第一个工具调用**是读本文件。
> 读完之前禁止 Grep / Glob / Bash / 业务文件 Read。

## 导航协议（SOP）

> 递归规则：进任何目录（模块 / 单元），第一步都是读该目录 `nav.md`。

```
1. 读本文件 → 「业务模块路由」按关键词粗筛模块；查规范 / 协议 / SDK 看「通用规范路由」
2. 读 {module}/nav.md → 关键词全集匹配到具体单元（feature/design 清单）
3. 读单元 nav.md → 按上下文闭包的「触发条件 → 读什么」，只读命中条目
   （spec / attention / adr / 依赖单元），命中即停，勿外溢
4. 需要模块级细节 → overview.md / architecture.md，命中即停
5. 推翻任何现状设计前 → 必查该单元与模块 adr/
6. 任一层 miss，或发现文档与代码不符 → 立即走「兜底与补全」回写（强制 / 立即 / 无需询问）
```

> 文件体系与写作规范见 [SPEC.md](SPEC.md)；回写规则全表见 SPEC.md §五。

## 兜底与补全（路由未命中时）

1. **横向比对**：读 2-3 个语义最近的 `nav.md`，**禁止跳过 nav.md 直接 grep**。
2. 仍未命中 → 兜底定位实际代码，判断归属，按 SPEC.md §五 R1–R3 回写（补关键词 / 建单元 / 加清单行），再继续手头任务。
